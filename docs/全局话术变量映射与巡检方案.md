# 全局话术变量映射与巡检方案

## 目标

建立一套不区分影楼、可提前配置并自动巡检的全局话术变量映射能力。系统在创建任务和导入名单时自动应用已发布规则，避免百应新增变量后出现参数遗漏或调用报错。

## 核心原则

1. 映射关系全局共用，不按影楼维护。
2. 映射在“字段映射中心”提前配置并发布；创建任务时不可临时编辑。
3. 百应变量名以 4.10“查询话术变量”接口返回值为准，必须精确匹配。
4. 创建任务与导入名单只使用已发布的映射版本快照。
5. 发现新增、删除、漂移或同步过期时，相关场景不可用于新任务或新名单导入。
6. 已创建任务不受后续映射变更影响。

## 数据流

```text
ERP / CRM 原始参数
        ↓
按数据来源选择字段映射
  ├─ ERP → erp_field
  └─ CRM → crm_field
        ↓
百应 CustomerInfoVO
  ├─ name
  ├─ phone
  └─ properties: { 百应变量名: 转换后的值 }
```

全局映射示例：

```text
百应变量“婚期”       → ERP: wedding_date      / CRM: marriage_date
百应变量“套餐意向”   → ERP: package_interest  / CRM: interest_package
百应变量“顾问姓名”   → ERP: consultant_name   / CRM: owner_name
```

字段映射中心只维护设置 `hideDefaultVar=true` 后接口实际返回的话术变量，不维护 ERP/CRM 的全量字段字典。“客户名称”“联系方式”由百应明确映射到导入 Body 顶层 `name`、`phone`，因此不进入 `properties` 字段映射；其余实际返回变量全部进入映射与就绪检查。

## 百应变量同步

### API 调用链

本项目统一按百应最新 OAuth v2 接入。后端使用 `AppKey + AppSecret + companyId` 获取 Access Token，并缓存至过期前 5 分钟；Token 无效时只允许重新获取一次。密钥与 Token 只存在后端，不进入前端、日志或数据库快照。

1. `POST /api/oauth/byai.openapi.company/1.0.0/list`，在 Body 中传 `accessToken`，获取该 Token 绑定的公司并校验配置的 `companyId`。
2. `POST /api/oauth/byai.openapi.robot/1.0.0/list`，在 Body 中传 `accessToken + companyId + robotStatus=2`，只获取发布过且可用于变量查询的话术，取得 `robotDefId` 和 `robotName`。`robotStatus=0` 可能包含已不存在、无法查询变量的历史记录，不进入映射巡检。
3. 对每组 `companyId + robotDefId` 调用查询话术变量接口：

```text
POST https://open.byai.com/api/oauth/byai.openapi.company.scenevariables/1.0.0/get
Content-Type: application/x-www-form-urlencoded

accessToken=<后端获取的 Token>
companyId=<公司 ID>
robotDefId=<话术 ID>
hideDefaultVar=true
```

4. 接口返回 `data.variables`。`hideDefaultVar=true` 过滤映射到导入 Body 顶层 `name`、`phone` 的默认变量，只把写入 `properties` 的话术变量纳入字段映射。

最新话术列表不返回独立 `sceneDefId`，平台以 `robotDefId` 的字符串形式同时作为内部场景稳定标识，并保留 `robot_def_id` 字段。

### 同步频率

```text
定时同步：每 6 小时
手动同步：字段映射中心提供“立即同步”
过期阈值：24 小时未成功同步
```

### 同步伪代码

```pseudo
for each company + robot:
  variables = querySceneVariables(companyId, robotDefId, hideDefaultVar=true)

  if request failed:
    keep last successful snapshot
    mark scene as STALE_SYNC
    create sync failure alert
    continue

  diff = compare(variables, latest_snapshot.variables)

  if new variables exist:
    create PENDING_MAPPING items

  if variables were removed:
    mark related mappings as REMOVED

  if same scene returns different variable sets across companies:
    mark scene as DRIFT_DETECTED

  save new snapshot and hash(sorted(variables))
  recompute scene readiness
```

同步失败时必须保留最近一次成功快照，不能把历史变量误删。

## 场景状态

| 状态 | 含义 | 是否允许新任务/新导入 |
| --- | --- | --- |
| `ACTIVE` | 已同步，全部变量均有已发布映射 | 允许 |
| `PENDING_MAPPING` | 发现新增变量，等待配置映射 | 不允许 |
| `DRIFT_DETECTED` | 同一场景变量集合发生不一致或变更 | 不允许 |
| `STALE_SYNC` | 超过 24 小时未同步成功 | 不允许 |
| `DISABLED` | 管理员手动停用 | 不允许 |

只有 `ACTIVE` 场景允许创建新任务和导入新名单。

## 全局映射规则

```ts
type GlobalVariableMapping = {
  id: string
  baiyingVariableName: string
  erpField?: string
  crmField?: string
  transformType: 'TEXT' | 'DATE' | 'MONEY' | 'ENUM' | 'TEMPLATE'
  transformConfig: object
  emptyPolicy: 'BLOCK' | 'DEFAULT'
  defaultValue?: string
  status: 'DRAFT' | 'PUBLISHED' | 'REMOVED'
  version: number
}
```

约束：

1. 一个百应变量名只能有一个生效的全局映射。
2. ERP 字段和 CRM 字段至少配置一个；导入时只读取当前来源系统对应的字段。
3. 所有非默认变量必须配置映射，或明确设置默认值。
4. `BLOCK` 表示值缺失时，该客户进入导入失败明细。
5. 百应变量名不可由前端手工修改或新增，只能来自同步结果。
6. 发布映射时生成不可变版本号。

## 创建任务逻辑

创建任务时不做映射配置，只做已发布映射的可用性校验。

```pseudo
scene = selected robotDefId
readiness = getSceneReadiness(scene)

if readiness.status != ACTIVE:
  reject task creation
  return "该话术变量映射未就绪，请前往字段映射中心处理"

mappingVersion = getPublishedMappingVersion(scene)
create task
save task.mapping_version_id = mappingVersion.id
```

任务页面展示：

```text
映射状态：已就绪
映射版本：v12
变量覆盖：6 / 6
最后同步：2026-09-03 10:00
```

## 导入客户逻辑

```pseudo
for each ERP/CRM customer:
  payload.name = sourceAdapter.readName(customer)
  payload.phone = sourceAdapter.readPhone(customer)
  payload.properties = {}

  for each required baiying variable:
    mapping = getTaskSnapshotMapping(task.mapping_version_id, variable)
    sourceField = source_system == ERP ? mapping.erpField : mapping.crmField
    value = transform(customer[sourceField], mapping)

    if value is empty and mapping.emptyPolicy == BLOCK:
      add import failure record
      skip customer

    payload.properties[variable] = value or mapping.defaultValue

send importTaskCustomer in batches of <= 10,000 records
```

导入百应的示例：

```json
{
  "companyId": 3212,
  "taskId": 13487,
  "customerInfoList": [
    {
      "name": "王女士",
      "phone": "13800000000",
      "properties": {
        "婚期": "2026-10-18",
        "套餐意向": "轻奢婚纱照"
      }
    }
  ]
}
```

## 字段映射页面

页面由三个区域组成：

1. **变量巡检**：最后同步时间、场景数量、正常/待映射/漂移/同步失败数量，以及“立即同步”按钮。
2. **待处理变量**：百应变量名、所属话术场景、变化类型、配置映射入口。
3. **全局映射规则**：百应变量名、ERP 取值字段、CRM 取值字段、转换规则、空值策略、发布版本、样例预览。

## 验收标准

1. 百应新增变量后，6 小时内可被识别并进入待映射。
2. 未配置的新变量不能静默进入任务导入。
3. 映射未就绪的场景不能创建任务。
4. 已创建任务使用创建时锁定的映射快照。
5. 导入失败可定位到具体客户、变量、原始值与失败原因。
6. 不同影楼共用同一套全局映射规则。
