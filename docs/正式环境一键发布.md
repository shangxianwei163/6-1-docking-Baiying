# 正式环境一键发布

## 固定目标

- 正式服务器：`8.160.187.243`
- 宝塔现有 Node 项目：`scheduling_paiyide_cc`
- 项目目录：`/www/wwwroot/scheduling.paiyide.cc`
- 正式地址：`https://scheduling.paiyide.cc`
- 宝塔面板必须绕过代理、直接访问服务器 IP。

本流程只更新上述现有项目，不创建新的宝塔项目，也不发布到 Sites。

## 日常发布

先把准备发布的改动提交并推送到 GitHub `main`，然后在项目根目录执行：

```bash
npm run release:production
```

脚本会自动完成：

1. 确认当前分支为 `main`、没有未提交的已跟踪改动，且本地 `HEAD` 与 GitHub `main` 一致。
2. 执行后端测试、类型检查、代码检查，以及前后端生产构建。
3. 只打包 Git 已提交文件与本次构建产物，并生成 SHA-256 校验值。
4. 通过专用 SSH 密钥上传产物，服务器校验后备份当前版本。
5. 依赖锁未变化时复用服务器依赖；锁文件变化时才在服务器执行一次 `npm ci`。
6. 更新 `/www/wwwroot/scheduling.paiyide.cc`，保留服务器环境变量和非发布托管文件。
7. 通过宝塔重启现有 Node 项目。`scripts/start-baota.mjs` 会先执行数据库迁移，再启动前端、API 与全部 Worker。
8. 验证健康检查、Token 认证行为、接口文档和线上 Git commit。
9. 如果重启后的基础验收失败，自动恢复上一版本并再次启动。

只验证构建与打包、不修改正式环境时执行：

```bash
npm run release:production:dry-run
```

## 本机私密配置

`.env.baota.local` 必须保留在本机且不得提交。字段模板见 `.env.baota.example`，其中包括宝塔登录信息、正式域名和专用 SSH 私钥的绝对路径。

私钥不得复制到项目目录、提交记录、日志、截图或对话回复中。

专用 SSH 通道已经完成初始化。仅在服务器重装、密钥失效或更换开发机器时，生成新的专用密钥并执行以下恢复命令：

```bash
npm run release:production:bootstrap
```

## 回滚与故障恢复

每次切换前的版本保存在服务器：

```text
/www/backup/scheduling-paiyide-releases/<backup-id>
```

正常情况下由一键发布脚本自动回滚。若自动化本身不可用，才通过 SSH 使用 `scripts/deployment/server-release.sh rollback <backup-id>` 恢复，并在宝塔中重启现有项目。手工恢复后仍需检查 `/health`、Token 认证和本次业务功能。
